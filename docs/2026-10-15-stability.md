# Windows 稳定性修复记录

## 目标与证据

- 修复代理页 SOCKS / HTTP 切换错误及等待过久。用户日志在 0.0.2 出现 E4002：`socks=` 被当成主机地址；当前前端仍有直接拆分旧版 `server` 的回退路径。
- 主窗口固定在视口内，内容区独立纵向滚动；长代理状态、窄窗口不能撑开页面。
- 默认直连方案允许编辑 hosts / 订阅选择，保持代理关闭、DNS 自动获取、不可删除。

## 执行计划

1. 增加代理旧格式解析回归测试，统一展示和表单填充的解析入口；限制重复提交，只有端口探测失败才提供强制开启。
2. 手动代理切换保留前置端口探测、注册表回读和快照；不再同步等待不能验证代理转发的直连外网探测。方案的严格校验保留。
3. 默认方案复用现有编辑器；后端按现有方案身份保护内置字段，只接受 hosts 选择，并测试持久化后的订阅展开。
4. 修复主窗口 grid/flex 最小尺寸和长文本换行；以 900×640、760×540 做浏览器验证。
5. 执行前端类型检查、构建、回归测试、Rust 测试和 Windows 构建；复核 diff。保留现有用户配置和系统网络配置。

## 验证基线

修改前：`npm run check` 通过；`cargo test --locked` 73 项通过。最终结果见后续验证记录。

## 实际修复与审查

- 原布局在长代理状态下将页面宽度撑到约 2606px；修复后两种窗口尺寸下页面宽度均等于视口，底栏可见，正文独立滚动。
- 额外复现并修复标签页请求竞态：延迟返回的 Hosts 页面不能覆盖后来选中的代理页。
- 代理失败报告在刷新后保留；仅 E3001 端口探测失败显示强制开启；清空方案端口后不再回填旧值。
- 独立代码审查发现脱离文档渲染会使日志初始滚动失效，已移到挂载后的动画帧处理，并加入浏览器回归。
- 第二轮独立审查未发现本次改动中其他高、中优先级问题。
